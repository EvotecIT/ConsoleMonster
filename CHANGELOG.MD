### 2.1.0 - the everyday path

## Public API

- Constructors return reusable widgets; `Show-Console` and `Show-ConsoleTable` display them. Records use `Show-Console -View List`, static inspectors use `Show-Console -View Tree`, and explicit hierarchies use `New-ConsoleTree`. `Show-ConsoleObject` is a rich interactive explorer.
- `New-ConsoleTable` owns table configuration through `-Property`. Charts and rules are built with `New-ConsoleChart` and `New-ConsoleRule`, then displayed with `Show-Console`. `Export-ConsoleFrame` accepts objects or widgets and returns text when no path is supplied.
- Live addresses use `WidgetId`, stored identities use `Key`, visible item text uses `Label`, and view headings use `Title`. Semantic styling uses `Role`, literal colors use `Color`/`BackgroundColor`, and text decoration uses `Decoration`.
- Item collections, tabs, menu results and numeric-column formats accept records in their parent definitions. `New-ConsoleStatusList -Layout Strip` builds phase strips; `New-ConsoleRegion` handles alignment and padding. Dashboard and app parameters configure headings and footers.
- `Update-Console` validates live updates. Custom C# targets receive events through `LiveSession.Post`. `Compare-ConsoleObject -Question` displays changes and returns the confirmation decision.
- `Enable-ConsoleFormatting` enables Output, FormatCommands, Errors, Streams and ReadLine by default. `-Include` and `-Exclude` adjust that set; `-ErrorLayout Compact|Standard|Detailed` selects error detail. Prompt, Help, Progress and GridView remain opt-in. `Get-ConsoleFormatting` reports the active features.
- Interactive snapshots use `-Mode Snapshot`. `Show-ConsolePresentation -ScriptPath` selects a demo script and optional `-Path` records it unattended; `Get-ConsoleDemo` exposes standalone script text through `.Source`. Recording exports use `-InputRecordingPath` and `-OutputPath`; frame exports and session recording use `-Path`. `-ChromeStyle None|MacOS|Windows|Linux` selects window decoration.
- The PowerShell module ships net472 and net8.0 payloads and bundles the Markdown and graphics add-ons. NuGet packages retain their existing target frameworks. Commander and file-operation application code live in `ConsoleMonster.CLI`, outside the library packages and module.
- Imports register only the documented allowlist of fully qualified type accelerators. Markdown display and export belong to `ConsoleMonster.Markdown`; the rendering core stays dependency-free.

- Animated slide exports use managed GIF with a useful first frame, a final hold and native slide dimensions. External video export is removed; OS-provided video encoders remain on the roadmap.
- Recording exports add Slow, Normal and Fast reading pace, persistent hold markers, chapter holds, source/chapter trims and chapter speeds across GIF, APNG, HTML and animated SVG. New casts preserve source timestamps so export idle compression stays reversible.
- Terminal exports share centred regular titles, Windows Terminal tabs, rounded body clipping and an 8 px page inset across HTML, SVG and slide graphics.

#### What's new
- Images inline: `Show-ConsoleImage -Path ./chart.png -Width 40` draws real pixels in Kitty and Ghostty (Kitty graphics), iTerm2 and WezTerm (iTerm2 inline images) and Windows Terminal (Sixel), half blocks on any other terminal with 256 colours or more, and `[image: name WxH]` in redirected, CI and no-colour output. `New-ConsoleImage` places an image inside panels and dashboards, and `ConsoleImage` in `ConsoleMonster.Graphics` takes PNG bytes, a file or a ChartForgeX render. `Get-ConsoleCapability` reports the protocol in `ImageProtocol`. See [Inline images](https://consolemonster.dev/docs/inline-images/).
- Apps can have screens without hand-wiring them. Adjacent `New-ConsoleScreen` commands (`AppScreens` in C#) make a screen stack with back navigation on Escape and Backspace, inputs inside screens, focus kept per screen and breadcrumbs in the header. Keys are declared once per input, screen or app (`-KeyBinding`, `KeyBinding`), and the footer is built from them, so it never lists a key that does nothing. `'1-12'` and `KeyBinding.Numbered` open numbered items, including two-digit numbers, and letter and digit keys work on other keyboard layouts. Dropdowns (`New-ConsoleSelect -Dropdown`), dialogs and toasts draw on an overlay layer above the content. `Show-ConsoleApp -KeyBinding` replaces `-FooterHints` and `-HandleInput`. Output written while an app runs goes into the app instead of below its footer, panels shrink with their borders in a short window, the command palette has one frame, and the debug socket's `tree` reports why each control has its size (protocol 2). See [Interactive applications](Docs/Interactive-Apps.md#screens-keys-and-the-overlay-layer).
- Your text is never rewritten: on the Basic and ASCII glyph tiers (conhost, redirected files, CI logs) only ConsoleMonster's own borders, markers, spinners and icons fall back, while labels, table cells and log lines keep their emoji and symbols. Redirected output (files, pipes, CI logs) is as wide as `COLUMNS` when it is set, through one width rule that every PowerShell command and `Get-ConsoleCapability` share. Output that cannot make links clickable prints `text (url)`.
- Apps can be tested, recorded and driven like web pages. `HeadlessTerminal` runs the full app with no terminal (scripted keys, clicks and resizes in, the composed screen out) behind the new `IConsoleDriver` seam, which the console also implements. `Invoke-ConsoleRecording -Headless -InputScript` and `LiveSessionOptions.Recorder` record what the user saw, including the log panel, footer and dialogs, and captured screens export to GIF, APNG, animated SVG and the HTML player. `BrowserHost` shows a headless app in a self-contained local page that sends keys and clicks back, and the opt-in `DebugSocket` (localhost only, token, secrets masked) lets agents read the screen and control tree and send input. See [the headless driver guide](Docs/Headless-Driver.md).
- `Matrix`, reference trees and grouped streaming tables provide reusable views for cross-tab results, linked hierarchies and incrementally arriving groups.
- The optional `ConsoleMonster.PowerShell.Display` package registers exact application types through runspace-owned leases. It preserves original pipeline objects and leaves unregistered values with native PowerShell formatting.
- Embedded displays preserve the host's foreground and background colors, including resets and streamed footers. Automatic streams sample up to 200 rows and check a 250 ms boundary on arrivals and completion. Quick completed scopes use a collected table or an optional detailed single-record view; open streams keep one stable grid. Collection status updates on arriving rows after one second, clears before the final view and leaves native warnings and errors intact. Redirected output and transcripts never receive the status line.
- Opt-in console views share compact health glyphs, assessment severity tones, headers, score gauges, legends and consistent spacing. After-label trees retain status and reference evidence; below-row table details include footer evidence, and repeat dimming stays consistent across buffered, chunked and windowed output.
- Matrix cells support status tones and data bars; reference trees retain value columns, basic markers and cycle identities. Card counts are optional, and colorless stacked bars use matching, distinguishable fill markers in their bars and legends.
- Streamed tables reserve identifying names before optional detail columns, measure values through their presenters and shorten long headers before allowing them to consume the row's width.
- Full-screen apps compose independent virtualized data grids, lazy cells, retained tabs, trees, date/range pickers and log viewports. Context footers follow the app registry; form dialogs and cancellable progress share the existing action host. Child processes use a real PTY/ConPTY with screen, mode and focus restoration and a bounded last-output view. `Show-ConsoleGrid` and `Show-ConsoleObject` use the shared controls and retain their output contracts. See [the full-screen controls guide](Docs/Full-Screen-Controls.md).
- Whole-session recordings preserve long lines and cursor-positioned dashboard repaints beyond 64 KiB. Streaming redaction keeps secrets private across reads, colour codes, markers and resizes; complete-record patterns have an explicit, documented fallback. Playback keeps completed synchronized redraws instead of sampling halfway through a repaint. The total `MaxBytes` cap is unchanged. Explicit destinations no longer wait on default-folder availability checks.
- Recorded terminal output gives equivalent cursor movement and redundant blank erasure one encoding while retaining real scrolling, pager states, synchronized redraws and hyperlinks. Combining characters retain the original blank-cell style when they make it visible. Unmodeled terminal controls retain their dependent output.
- Basic and ASCII glyph tiers use readable, single-cell prefixes for hints, search, success, checkboxes and playback controls. Unsupported decorative symbols fall back safely, whole joined emoji use one fallback, and localized prose keeps its original spelling.
- Native flow strips show labelled hops, status glyphs, severed edges and one side branch, with a vertical layout in narrow terminals. PowerShell item commands and pipeline rows compose with live updates and exports. The TLS verdict showcase pairs the flow with a numbered ledger, multi-column context and a double-bordered verdict for healthy and expired certificate chains.
- Gallery programs declare typed fixture data directly and run without capture parameters. The runner drives native prompts and live checkpoints externally; `LiveSession.Delay` and `Wait-ConsoleDashboard` share cancellable waits, while `New-ConsoleForm -PageDescriptions` exposes per-page guidance in PowerShell. Loaded choice defaults retain their selections and equivalent-command defaults. `CommandLine.Build` formats named command arguments with shared quoting rules.
- Everyday output now covers JSON/REST and CSV records, richer commands/modules/history, PowerShell 7 ping and .NET DNS/IP objects, plus Windows DNS, adapters and connectivity results. JSON expands small nested values and envelope item tables with depth and row limits; CSV strings keep their spelling and header order with numeric/date alignment. Module groups name each module once and preserve user/system path origins. Network labels use readable names such as IPv4 and Timed out. Narrow table cards retain captions and explicit column truncation.
- `Show-Console -View Markdown` reads CommonMark with pipe tables, highlighted code, link fallbacks and automatic interactive paging. The optional `ConsoleMonster.Markdown` package uses OfficeIMO.Markdown; the rendering core stays dependency-free. `-Path`, `-Content` and `-NoPager` work on PowerShell 5.1 and 7, with complete static output for captures and unattended sessions.
- Thirty-six self-contained PowerShell and C# demo pairs cover small starters and full showcases, with metadata, deterministic frames, replays, thumbnails and downloadable sources. The catalogue includes use cases, source line counts and featured showcases. `Get-ConsoleDemo` browses demos; the `.Source` property supplies a script, `Show-ConsoleDemo` runs it, and `dotnet new consolemonster --demo <slug>` starts a project from the same C# source.
- `Prompt<T>.Snapshot()` and `Read-Console* -Mode Snapshot` render an initialized prompt without reading input or returning an answer. `Lanes.Add(Lane)` preserves complete lane state, including start/finish times; lane definitions expose the same timing fields.
- Menu choices accept typed description, badge and disabled selectors through `Choice.From`; PowerShell exposes per-choice `-ChoiceBadge/-ChoiceDisabled` on menu items and `-Selections` for presets that configure several items. Loaded choices preserve requested selections and discard unavailable values; asynchronous loaders also work in inline menus.
- Scripted typed demos and live presenter controls share a real PowerShell PTY with OSC 133 readiness. `ConsoleMonster.Graphics` adds PNG, GIF and APNG exports. Slide presets share centred window composition, content fitting that trims unused rows and columns or keeps the full terminal, rounded corners and theme, solid or gradient backgrounds; the core stays dependency-free.
- Unix everyday views show file modes, owners and readable file/link sizes with blank directory sizes, omit Windows file-version and process-memory noise, and preserve explicit property selections. Overview summaries use product OS names, one-shot CPU samples, visible disks and primary IPv4 networking with global IPv6. Showcase defaults follow the host, long labels share width with values, and Mac text fields support word editing and `?` help. Interactive VT startup can detect light backgrounds through a bounded OSC 11 query.
- Parser-independent command-line help metadata supports grouped commands, positional values, option defaults and notes, with localized labels. Shared CLI integrations can grow run totals, preserve narrow table columns and tree labels, and apply scoped profile policies without replacing their terminal target.
- `LiveRun` monitors large batches with finished-item scrollback, a height-bounded dashboard, pinned warnings and failures, queued work, group progress and a full final summary. PowerShell exposes `Start-ConsoleRun`, `Update-Console -Run` and `Complete-ConsoleRun`; CI uses append-only output with count/time progress updates. Optional keys control the log and groups without pausing work.
- HTML and SVG exports, including recording players and animations, support MacOS, Windows, Linux and None window styles through `ChromeStyle` / `-ChromeStyle`. Select None to omit the frame; styles use generic vector controls and the export theme's surface and muted colours.
- Whole terminal sessions can be recorded with `Invoke-ConsoleRecording -Interactive` or `Invoke-ConsoleRecording`, including native output, colours, resizes and chapters. Local asciicast v2 files export through the existing HTML player, animated SVG, text, Markdown and final-frame SVG. Output redaction, idle trimming, a size cap and a labelled PowerShell-only fallback are included.
- `Show-ConsoleOverview` collects a read-only host snapshot with CPU/memory and disk bars, network addresses and safely available service, update/reboot and security observations. Select sections or return the snapshot with `-AsObject`; applications can register their own probes. Wide output fits one screen, while narrow layouts stack without hiding volume or login rows.
- `Show-ConsoleObject` explores nested members with lazy expansion, breadcrumbs, search and keyboard selection. `-PassThru` returns the selected value, and `-PassThru Path` returns its PowerShell expression. Use `Show-Console -View Tree` for static inspection.
- HTML and SVG frame titles reserve space after the window dots, truncate with an ellipsis and retain the full title as a tooltip. Very narrow frames keep all three dots visible and hide titles that cannot fit.
- `New-ConsoleChart` constructs all six numeric chart kinds from records and samples through the shared C# `Chart` factory. Use pipeline sorting and selection before construction, explicit histogram edges and `Export-ConsoleFrame` for text captures.
- Everyday Get-Member views show each type name above its table and use full-width member-group sections with counts, preserving native column overrides and script-safe output.
- `Compare-ConsoleText` compares strings or files with line numbers, word highlights and collapsed unchanged ranges. It uses side-by-side output from 120 columns, inline output below that, `-Context`, `-IgnoreWhitespace` and plain unified text with `-AsUnified`. The shared text engine uses linear auxiliary memory and bounded alignment work.
- `Enable-ConsoleFormatting -Include Errors` opts into compact host errors: message first, highlighted invocation and marker, category/target, folded causes and `-ErrorLayout Detailed` stacks. Captures, files, jobs and transcripts retain native error rendering. `Show-Console -View Error -ErrorLayout Compact` uses the same view explicitly.
- `Enable-ConsoleFormatting -Include ReadLine` themes loaded PSReadLine syntax, selection and available inline predictions; `Streams` also styles native progress while preserving its view. Shared native preferences follow the latest applied installation across runspaces; the last owner restores the first exact baseline, including after user edits. ReadLine is included in All. All keeps Write-* cmdlets native and excludes the legacy Progress alias feature.
- `Enable-ConsoleFormatting -Include GridView` supplies an `Out-GridView` fallback only where the desktop command is unavailable, using `Show-ConsoleGrid` for titles, browse/wait mode and original-object selection. Working native commands stay untouched; disable and module removal restore saved functions and aliases exactly. GridView remains opt-in.
- Optional `Enable-ConsoleFormatting -Include Prompt`: shortened path, bounded asynchronous cached git state, last-command status and completed-history duration above two seconds; exact prompt restoration and protected oh-my-posh/Starship opt-in with `-Force`.
- Live tails highlight navigation keys, show a warning-colored paused-history state with applied new-line counts, and hide zero discarded-history counts. Source timestamps use the same compact time column at every width, include dates across retained source days, and accept an explicit `Watch-ConsoleLog -TimestampFormat` or core option.
- `Watch-ConsoleLog` follows files across observed truncation and rotation, or local Windows event logs, using a scrollable log view with source timestamps, level colours, literal filters and highlights. Scrolling pauses following; End resumes it. Redirected and plain output preserve original lines and never read input. The zero-dependency `FileLogTail`, `LogTailView` and `ConsoleLogTail` APIs share the same engine.
- Windows-style form command lines preserve quoted paths with trailing backslashes and values containing embedded quotes using native Windows argument-quoting rules.
- Hosted-service dashboard durations measure each service's lifetime with a monotonic clock and freeze at its own stop, completion or failure, preserving the result through host shutdown.
- `Enable-ConsoleFormatting -Include Streams` colors native warning, verbose and debug messages with the active theme, plus errors on PowerShell 7.2+. Included by default; disabling or removing the module restores the original settings. PowerShell keeps its stream commands, prefixes, preferences, redirection and transcripts.
- One value-shaping layer for every command (`ConsoleMonster.Values`): columns come from `-Property`, a registered view, PowerShell's own table view, the default display set or a fallback; dictionaries are records, arrays are joined in cells, records are titled like `pwsh (90836)`, secure strings are masked, slow or hanging getters are bounded and marked. `Register-ConsoleView -Shaper` and `ValueShaper.Register` add your own.
- Console output reaches every consumer: piped commands get plain lines, PowerShell 7.2+ captures a command typed at the prompt (`$x =`, `>`, `-OutVariable`, transcripts), and `Export-ConsoleFrame -Format Text` captures widgets on both PowerShell runtimes. Widgets and renderings draw themselves at `Out-Default` (`ConsoleMonster.format.ps1xml`, generated from the widget types). `Show-Console` follows the same model.
- `-GroupBy` headings are labelled rules with counts ("2 of 3" when `-Top` cuts a group) and the group count in the footer; the grouped column is left out (`-ShowGroupColumn`), groups are sorted (`-NoSort`).
- Numbers in a column share the decimals the column needs; short values never wrap; long text stops at three lines (`-Wrap`, `Table.WrapLines`, `TableColumn.Unlimited`).
- One status vocabulary with PowerShell's words (Success, Information, Warning, Error, Failed, Verbose, Debug, Skipped) for `-Status`, `Write-ConsoleLogEntry -Level` and status columns, with markers in every command and in log regions.
- One date format everywhere (`yyyy-MM-dd HH:mm`, local time, culture-independent); numbers follow the culture.
- `Show-ConsoleTable -View Record`, `New-ConsolePanel -Content` with any object, bar chart thresholds (`-Warning`, `-Critical`), check marks for finished progress, a shorter error view, "not compared" in change summaries, shorter default trees for wide objects.
- `Enable-ConsoleFormatting -ProfileSnippet`; built-in views for Get-Command, Get-Module, Get-WinEvent, Get-NetIPAddress and Get-Volume; the `fct` and `fcl` aliases; `Example-LoginOverview.ps1`.
- Widgets for runs of many items: `CellMap` (one cell per item, a symbol per state in every tier, an active window that follows the running cell), `SummaryBar` (bar, done of total, percentage, time left, counters with zeros dimmed), `ActivityList` ids and elapsed time, `Lanes` options (`DimPending`, `BoldActive`, `ShowRunningCount`, `CollapseWhen`) and `FooterBar.Segments`. The test-run view uses them: the summary line, the files with skipped ones folded, the outcome of every test, the running test with its time, then the failures.
- `Watch-Console { … } [-Interval 2] [-Count n] [-Differences]` reruns a script block and shows its latest output (with its errors and warnings under it, changed cells marked with `-Differences`); a failed run shows its error and the watch goes on. Piped on or without a console, it prints every run.
- `Invoke-ConsoleRun` runs a script block for every input item, one at a time in the caller's scope or with `-Parallel -ThrottleLimit n` in runspaces (`$using:name`, `-TimeoutSeconds`, Ctrl+C), on Windows PowerShell 5.1 and PowerShell 7. A live view shows the summary line, a cell per item, the running items and the failures; the output comes in input order (`-Unordered` for completion order) and failures are error records. Without a console it prints a line per item and a summary. `ConsoleRun.ForEachAsync` and `RunMonitor` do the same from C#.
- `Enable-ConsoleFormatting -Include Errors` provides opt-in compact error rendering, and `Streams` styles native progress and diagnostic streams while preserving PowerShell commands and preferences. `Disable-ConsoleFormatting` restores the previous settings.
- `Show-ConsoleHelp <command>` shows a command's help from Get-Help: synopsis, syntax with parameter names, value types and optional parts told apart, a parameter table (type, required, position, pipeline input, default, description), highlighted examples, inputs, outputs, notes and links; cmdlets, functions and scripts with comment-based help on 5.1 and 7, plain lines through a pager. `HelpView` and `HelpTopic` are the C# side.
- New package `ConsoleMonster.Extensions.Logging`: an `ILoggerProvider` (`logging.AddConsoleMonster()`) with the level tags and colours of `Write-ConsoleLogEntry`, a timestamp format, short or full categories, scopes, event ids and exceptions; entries go into a running dashboard's log region and print as plain lines when redirected. Depends only on Microsoft.Extensions.Logging.Abstractions.
- New package `ConsoleMonster.Hosting`: `services.AddConsoleDashboard()` shows the generic host's hosted services (waiting, starting, running, stopping, stopped, completed, failed, with how long and the failure message), entries reported through `IConsoleDashboard` and the log, and draws nothing when redirected, in CI or as a service. Depends only on Microsoft.Extensions.Hosting.Abstractions.
- New package `ConsoleMonster.Templates`: `dotnet new consolemonster` creates an app with a menu, a status report, logging, the host dashboard and native AOT publishing.
- `LogTags` exposes the level tags and styles of the log region. `Docs/Proposals/Command-Line-Layer.md` lays out the options for a command-line layer.
- Renderings (what `Show-Console*` writes on PowerShell 7.2+) are out of band at `Out-Default`, so they show on their own also between the rows of another table; widgets keep `Format-List *`.
- Linux and macOS: locale-aware glyphs (LC_ALL, LC_CTYPE, LANG), no cursor queries on Unix, portable display paths; CI on Linux for every push and macOS for pull requests.
#### Behaviour changes
- macOS recordings acquire a controlling terminal, so Ctrl+C, `/dev/tty` prompts and resize signals reach the child. Recording titles are set once, and terminal input is restored before recorder finalization. Unix API recordings use `$SHELL` or the platform shell and default missing child locales to UTF-8.
- Live runs preserve Unix Ctrl+C handling with keyboard controls enabled. Form and menu command copying uses `ClipboardService` with pbcopy, wl-copy or xclip; SSH uses OSC 52. The duplicate `Interactive.Clipboard` API is removed, and pbcopy receives a UTF-8 locale.
- Frame exports extend a uniform native terminal background through the surrounding padding, so Light captures fill the window body without an inset panel.
- A single object in `Show-ConsoleTable` stays a one-row table, as with `Format-Table` (a single dictionary is still shown as a record); use `-View Record` for labelled fields.
- `TableColumn.MaxLines = 0` now follows `Table.WrapLines` (3 by default) instead of meaning no limit; use `TableColumn.Unlimited` (in PowerShell column hashtables `MaxLines = 0` keeps meaning no limit).
- `Show-ConsoleGrid` uses a table fallback when rich interaction is unavailable; explicit unattended interaction mode does not fabricate a selection.
- `New-ConsolePanel` script blocks show their stray output (the number `ArrayList.Add` returns, a `$true`) instead of dropping it.
- Inside scripts and functions, and on Windows PowerShell 5.1, Console display commands draw on the screen as before; use `Export-ConsoleFrame -Format Text` to capture a constructed widget.
- Activity lists (Write-Progress under `Use-ConsoleProgress`, dashboards) show each activity's elapsed time on the right (`ActivityList.ShowElapsed`), and an activity without a percentage spins instead of showing a waiting circle.
- The test-run view's header keeps the title, status and clock; the counts moved to the summary line under it.
- Widgets support object initializers and property-named fluent calls through `ConsoleMonster.Building.Ui`. The build-time generator emits one extension class per namespace; consumers need no runtime reflection or analyzer. Typed tables use `Table.For(items)` or `Ui.Table(items)` with expression-based columns. PowerShell, initializer and fluent gallery programs share the same data and rendered output.
- Replay shows one frame: a recorded `Dashboard`'s own header and footer are not replayed, and its title (the default run name in `Show-ConsoleReplay`), subtitle and status show in the player's header.
- Redirected dashboards no longer record their own output again: the log lines that the PowerShell host wrote back through `Console.Out` came back as `$log` "out" events about every 60 ms (a bug that predates 2.0's replay work). `LiveSession.SuspendCapture()` lets a host write a session's output without capturing it.
- Change tables list an added or removed object's compared properties on their own lines (`ObjectChange.Values`), up to `ChangeView.MaxProperties` (6), then "+N more" with `ChangeView.MoreHint` ("-PassThru or -View SideBySide" from the cmdlets); the side-by-side view lists them all.
- The HTML recording player is one native asset (`ConsoleExporter.PlayerScript`, `ConsoleExporter.PlayerStyles`, embedded `player.js` / `player.css`) with a data format (`Recording.ExportPlayerData`, `Export-ConsoleRecording -Format PlayerData` or `-OutputPath *.json`) and a `data-cm-recording` contract, so sites include the script once for many players; it rewrites only changed rows, wakes at the recording's frame rate, updates the clock and position once a second, pauses off-screen and in hidden tabs, autoplays one player per page and none under reduced motion (headless Chromium, 120x36 busy recording: main thread 4.7% to 2.1%, renderer CPU 9.8% to 4.1%, 0% off-screen, no long tasks).
- Rewinding runs: `Show-ConsoleReplay` and `ReplayPlayer` (play/pause, speed, frame stepping, a timeline with markers, jumps to markers, failures, warnings and log entries, log search; full screen or inline; markers printed as lines without an interactive console), `ReplayMarker.From`, `LiveSession.Mark` / `LiveSession.MarkerTarget`, opt-in automatic recording (`LiveSessionOptions.AutoRecord`, `AutoRecordMaxBytes`, `AutoRecordFolder`, `RecordingName`, `DefaultRecordingFolder`, `LiveSession.RecordingPath`, `Invoke-ConsoleDashboard -AutoRecord`), and region swaps recorded as pictures (markup snapshots of the new content and of later changes inside it) so they replay faithfully.
- Object comparison and the what-if pattern: `ObjectDiff`, `ChangeSet`, `ObjectChange`, `PropertyChange`, `DiffOptions`, `ChangeView` (summary, table, side by side, unified, line diffs) and `ChangePreview` (typed confirmation for removals); `Compare-ConsoleObject` (with `-PassThru`) and `Compare-ConsoleObject -Question` (honours `-WhatIf` and `-Confirm:$false`, returns the decision).
- Identifier columns (Id, ProcessId, PID, ports, Index, Year...) are no longer grouped with thousands separators or totalled: `IdentifierPresenter`, `CellPresenters.Identifier` and the `Identifier` column option.
- Header bars keep the title on narrow windows; the right side gives way (free text, then the clock, then the status is shortened and dropped).
- `Terminal.WriteMarkup` / `Write-ConsoleText -Markup` wrap long lines at word boundaries in interactive output (redirected, CI and plain output keep whole lines).
- Empty text keeps the existing value wherever null does (phase, status and lane labels and details, spinner and activity text), so `$null` passed from PowerShell no longer blanks a label.
- Terminal progress indicator (OSC 9;4): `TaskbarProgress`, `ITaskbarProgressSource` on progress bars, lanes, spinners, activity lists, dashboards and the test-run view; live sessions, the status line and `Terminal.Status` drive it and clear it at the end, on Ctrl+C and on exit; only in Windows Terminal or ConEmu, never in CI, redirected or plain output; `CONSOLEMONSTER_TASKBAR=0`, `LiveSessionOptions.TaskbarProgress` and an opt-in bell (`NotifyOnFinish`).
- `Show-Console` and `ConsoleView` (`Decide`, `Auto`, `BuildTable`, `BuildTree`, `BuildChart`): inspector, table, cards (`Table.AlwaysCards`), tree, chart, code or text by the shape of the data; presenters by member name and type (`CellPresenters.ForMember`, `StatusEnumPresenter`); `-View Grid` opens the interactive grid.
- Opt-in default formatting: `Enable-ConsoleFormatting` / `Disable-ConsoleFormatting` (session-scoped native output adapters) and `Register-ConsoleView`; files, processes and services built in; redirected output, pipelines, `Format-*`, `Out-String`, jobs and remoting are unaffected.
- Targets: `ITerminalTarget` with `ConsoleTarget`, `RecordingTarget` (`TestTerminal.Target`, `MatchGolden`), `WriterTarget` and `NullTarget`; `Terminal.Use(target)` scopes the static methods (async-local), `Terminal.DefaultTarget`, `LiveSessionOptions.Target`, `InteractiveOptions.Target` and `target.Write/WriteMarkupLine/Status` extensions; the `target` example shows the library pattern.
- Progress columns: `Lanes.Columns` and `ProgressBar.Columns` with `ProgressColumns` (Spinner, Description, Bar, Percent, Count, Elapsed, Remaining, Rate, ByteRate, Results, Status, Custom), smoothed rate and ETA over `RateWindow`, `HideCompleted`, `CollapseWhenFinished`, `Transient`, priority-based column dropping and column summaries in the stream heartbeat; `-Column`, `-HideCompleted`, `-CollapseWhenFinished` and `-Transient` on the cmdlets.
- Built-in labels translated to Polish, German, Spanish, French and Italian (`PromptLabels.For`, `WidgetLabels`, `TerminalProfile.WithLanguage`, `CONSOLEMONSTER_LANGUAGE`), following the UI culture; `Table.TotalLabel` defaults to the translated word.
- Replaceable regions: `RegionWidget`, `LiveSession.Region(name).Set(widget)`, `RegionHandle`, `New-ConsoleRegion` and `Update-Console -Content`; swaps go through the update queue, keep the surrounding frame and register live widgets in the new content. `LiveEvent.Payload` carries in-process objects (not recorded).
- Keyed live tables: `LiveTable` with `LiveTableHandle.AddRow/UpdateRow/RemoveRow/Clear`, stable column widths, `MaxRows` (recent rows) and `SortColumn`; `New-ConsoleTable` and `Update-Console -Row`; `Table.ClearRows`.
- Emoji and symbol fallback per glyph tier (`SymbolFallback`, extensible), applied to markup, rich text and table cells before measuring; opt-in `:shortcode:` emoji (`Markup.Shortcodes`, `Shortcodes`, the `Emoji` cell presenter).
- `Use-ConsoleTarget` (file, writer, target or string); PowerShell output follows a non-console target. The Pester view and the render-error frame are translated too.
- Spectre markup compatibility: the 256 xterm colour names (`[cadetblue]`, `[grey50]`, `[deepskyblue3]`, numbered duplicates such as `[blue3_1]`), `[link]url[/]` next to `[link=url]text[/]`, OSC 8 only for http, https, mailto and ftp targets (the exporters' filter, now applied to all terminal output), closed unknown tags removed with their text kept, `Markup.Strict` / `Markup.Parse(..., strict: true)` to throw instead, `Markup.Interpolate` for escaped arguments, and `EscapeMarkup()` / `RemoveMarkup()` string helpers. Colliding names follow one rule: in markup a name is the palette colour (`[darkred]` is palette 52), in `-Color` and ConsoleColor parameters it keeps the Write-Host meaning (`grey` spells Gray); `console.<name>` and `palette.<name>` ask for either meaning in both places.
- `Terminal.WriteMarkup` no longer ends the line (Spectre's `Markup`); `Terminal.WriteMarkupLine` does. `Write-ConsoleText -Markup -NoNewLine`.
- `Terminal.Status` / `Terminal.StatusAsync`: a one-call spinner status with `ctx.Update(...)`, removed when the work ends, plain lines in redirected and CI output.
- `Terminal.Clear()`, `Terminal.HideCursor()` / `ShowCursor()` (restored on exit and Ctrl+C), no-ops in redirected and CI output.
- `ROADMAP.md` (decisions, next rounds, backlog) and the one-version policy for products in the README.
- `Write-ConsoleText -LogFile` keeps an existing log's encoding (byte order mark, or UTF-16 text without one), so Write-Color's UTF-16 logs stay UTF-16; a contradicting `-Encoding` warns. `ConsoleLogFile.DetectEncoding`, `KeepExistingEncoding`, `EncodingSpecified`.
### 2.0.0 - prototype (unreleased)
#### What's new
- Rebuilt as a zero-dependency .NET library (netstandard2.0, net472, net8.0) plus a thin binary PowerShell module for Windows PowerShell 5.1 and PowerShell 7.
- Terminal capability detection with `CONSOLEMONSTER_COLOR`, `CONSOLEMONSTER_GLYPHS`, `CONSOLEMONSTER_MODE` and `NO_COLOR` overrides; Unicode-safe output through `WriteConsoleW`.
- Spectre-compatible markup, semantic themes (dark, light, high contrast) and Full/Basic/ASCII glyph tiers.
- Widgets: text, rule, panel, table, tree, key/value, status list, spinner, progress, lanes, phases, bar and stacked bar, sparkline, histogram, braille line/scatter chart, log region, logo and dashboard; layouts Rows, Columns, Grid, Padding, Align and Stack.
- Live sessions: thread-safe updates coalesced at about 15 frames per second, console and PowerShell stream capture, Ctrl+C restore, JSON-lines record and replay (the replayed clock follows the recorded timeline), optional `[mm:ss]` prefixes on stream-mode lines (on by default in CI).
- Bars come in `Line` (progress and lanes default) and `Block` (bar and stacked chart default) shapes.
- Table width negotiation: column priority, minimum and maximum widths, overflow (wrap with a line limit, truncate, middle truncation, never), hidden-column footer, stable widths in live tables; record cards below a configurable width and a record view for single records.
- Groups with subtotals, totals (sum, count, average, minimum, maximum) and "Showing N of M" top-N.
- Cell presenters shared by tables, cards, key/value lists and trees: status, number, bytes, duration, date (absolute, relative, both; time zone), boolean, in-cell data bar, sparkline and progress, OSC 8 links; tone rules by threshold; readable without colour.
- Object inspector for .NET objects, PSObjects, dictionaries and `JsonElement` (net8.0) with depth and item limits, cycle detection, include/exclude and ordering; reflection isolated in one member source.
- `Show-ConsoleTable`, `Show-Console -View List` and `Show-ConsoleTree`: Format-Table style `-Property` (calculated properties, column option hashtables), DefaultDisplayPropertySet, `-GroupBy`, `-Total`, `-Top`, `-Width`, `-PassThru`.
- Live sessions handle window resizes (full redraw, coalesced while dragging), viewport scrolling, font changes (conhost font polling, width re-probe after Windows Terminal resizes) and windows that are too small (reduced layout by panel priority, then a one-line status).
- Light/dark background detection in conhost and `CONSOLEMONSTER_THEME=light|dark|auto`.
- Wrapping breaks after spaces, then after separators (path, list and query separators before dots, dashes and colons), then by character; `LogRegion.Wrap` wraps long log entries.
- Explicit culture for numbers and dates: `CONSOLEMONSTER_CULTURE`, `TerminalProfile.WithCulture`, `LiveSessionOptions.Culture` and `-Culture` on the Format cmdlets (default: the current culture).
- Outside a real local console (jobs, remoting, SSH, the ISE, redirected output, transcripts) cmdlets write through the PowerShell host like Write-Host, so jobs complete, transcripts record and `6>&1` captures the output.
- Host output keeps colour: coloured host UI writes on a real console with a transcript and in the ISE (plain lines in the transcript), coloured Write-Host-style records in jobs and remoting; redirected output stays plain.
- Rich text: multicolour spans (ConsoleColors exactly as Write-Host shows them, theme roles, hex/RGB, decorations, links, gradients) accepted in every widget, safe by default (data stays literal), with `RichText`/`RichTextBuilder` in C# and `New-ConsoleText` in PowerShell.
- `Write-ConsoleText` with Write-Color parameter parity plus markup, styles, gradients, padding, wrapping, split lines and Text/CSV/JSON-lines logs; `Show-ConsoleStatusLine` for an updating status line.
- Print-once output reads the window size on every write.
- Sentinel dates show as "never" and unbounded durations or non-finite numbers as a dash, instead of throwing; charts skip non-finite values.
- Stream and plain output sanitise escape sequences and control characters.
- Dashboards report unknown widget names, failed updates, failed frames and early ends through the host; `LiveSession.GetCounters()`; a dashboard that cannot start leaves the screen untouched.
- The object inspector has a node budget (`MaxNodes`, `-MaxNodes`), skips blocking getters and lets Ctrl+C through.
- Input core: Windows console keys through `ReadConsoleInputW` (Ctrl/Alt combinations, Shift+Tab, function keys, AltGr, pastes, resizes, focus), VT input decoding, scripted input for tests and demos, and one keyboard owner shared by prompts and live sessions.
- Prompts: confirm (with typed confirmation), text, secret, number, selection, multi-selection and path, with fuzzy filtering, groups, hotkeys, badges, previews, inline validation, typed results, line-based and accessible fallbacks, and defaults or a clear error when nobody can answer.

- Menu actions: console output, Write-Host, warnings and errors are collected and shown as a toast or an output dialog instead of drawing over the app; async actions ask through the menu's thread; a blocked Run shows its problem count and opens the item that fixes it; leaving a form with unsaved changes asks to discard them.
